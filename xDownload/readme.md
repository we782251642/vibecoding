# 一、运行方式

## 1.1 环境与基本命令

Node.js 20+，无需安装依赖；内置代理需 Node.js 22.21+ 或 24.5+。

```powershell
node ./download-media.mjs "JSON文件路径"
```

例如（在脚本所在文件夹执行）：

```powershell
node ./download-media.mjs "./bookmark-gallery-likes-2026-11-11.json"
```

## 1.2 交互选择

类型：1 = 仅图片，2 = 仅视频，3 = 图片和视频。
随后显示总数、已下载数、待下载数；输入本次数量，0 = 全部。Ctrl+C 取消。

## 1.3 可选参数

--dry-run：只检查，不访问链接、不修改文件。
--retry-failed：仅重试 JSON 标记或历史报告中的失败项。
--proxy http://127.0.0.1:7890：临时覆盖默认代理。

可修改参数集中在 `download-media.mjs` 顶部的“可配置常量”区域；以下说明描述默认设置。

# 二、目录与配置

## 2.1 固定下载目录

OUTPUT_DIRECTORY 常量控制输出目录，默认脚本所在文件夹下的 XD。
路径不受命令行当前目录影响，不再接受命令行输出目录参数。
XD/log：报告、校验记录和检查点；XD/photo：图片；XD/video：视频。
仍可读取旧版根目录及中文目录中的文件和日志，不自动移动历史文件。

## 2.2 代理配置

PROXY_URL 常量控制默认代理；设为 '' 关闭自动代理。

# 三、下载与命名

## 3.1 数据结构

从 posts[].media[] 下载 photo.url 或 video.videoUrl，不下载视频封面。

## 3.2 文件命名

作者名称_帖子名称_发表日期时间_媒体序号_类型.扩展名。

发表时间取 `postedAt`，默认北京时间，格式为 `YYYY-MM-DD_HHmmss`，可通过 `POST_DATE_TIME_ZONE` 调整。缺失或无效时使用“未知日期”；重名时追加短标识，避免覆盖。已有文件仍按历史记录复用，不自动重命名。
作者优先 author.name，其次 author.handle；帖子优先 name，其次去链接后的 text。
作者最多 32、帖子最多 48 个 UTF-16 单元；处理非法字符及缺失名称。

## 3.3 进度与重试

显示速度、已下载、总大小、剩余量和预计时间；未知大小会明确标注。
不单独查询远程大小；最多并发 4 个文件，每个最多尝试 3 次。

# 四、去重、校验与状态

## 4.1 跳过与完整性检查

按媒体地址对比历史记录，通过大小及 SHA-256 校验后跳过，无需远程请求。
无记录或文件损坏时重新下载；检查非空、响应大小和传输结束后才保存正式文件。
未提供大小时不能证明源文件完整；请保留 log/download-state.json。

## 4.2 输入文件标记与恢复

每项处理后写回 download 状态：pending / downloaded / failed。
首次写回前保留 .before-download.bak；文件占用时重试，仍失败则保存检查点。

## 4.3 报告

log/download-report_年月日_时分秒_毫秒_唯一标识.json，使用北京时间。
保留历史报告，兼容旧版 download-report.json；失败重试保留未选类型的记录。

# 五、分批整理媒体文件

## 5.1 运行方式

`download-media.mjs` 下载结束并保存报告后，会自动执行同目录的 `organize-media.mjs`，无需额外命令。仅部分文件下载失败时，仍会整理已经下载的文件，并保留失败退出状态。没有待下载项时也会整理；预览、取消输入或流程异常中止时不整理。

脚本顶部 `AUTO_ORGANIZE = true` 控制此行为，设为 `false` 可关闭。自动调用时会传入下载脚本的实际输出目录，因此修改 `OUTPUT_DIRECTORY` 后也会整理对应目录。整理失败会输出错误并返回失败状态，已保存的下载报告不受影响。

`organize-media.mjs` 位于 `xDownload` 文件夹，默认整理该文件夹下的 `XD`，不受当前命令行目录影响。在 `XD` 目录中执行：

```powershell
node ../organize-media.mjs
```

仅预览数量、不移动文件：

```powershell
node ../organize-media.mjs --dry-run
```

请在下载完成后运行，避免下载和整理同时修改文件。

## 5.2 分组规则

`photo` 和 `video` 分别统计。文件超过 100 个时，按文件修改时间（通常是下载写入完成时间）从早到晚排序，依次放入 `1`、`2`、`3` 等目录，每组最多 100 个，最后一组保留余数。编号代表时间先后；文件夹内的显示顺序由文件管理器的排序设置决定。

不再根据文件名中的帖子发表日期排序，因此后下载的旧帖子也会排在末尾；时间相同时按文件名排序。手动修改文件或复制时改变修改时间会影响顺序。下载时已有编号目录会优先写入最后一个目录，达到 100 个后新建下一编号目录；尚未分组时仍写入根目录。下载结束后再自动整理。重复运行会同时检查根目录和现有编号目录，将新文件重新排序分组。未分组且不超过 100 个文件的目录保持原样。不移动 `.part` 等临时文件，不跟随符号链接，遇到同名文件会停止以避免覆盖。

顶部常量 `OUTPUT_DIRECTORY` 配置输出目录，`FILES_PER_FOLDER` 配置每组上限，应与下载脚本的 `FILES_PER_FOLDER` 保持一致。

## 5.3 下载记录兼容

下载脚本支持 `photo/1/文件名`、`video/2/文件名` 等路径。原记录指向的文件被移动时，会按文件名查找实际位置，并核对大小和 SHA-256；通过后跳过下载，并把新路径更新到本次报告、校验记录及输入 JSON。整理脚本本身不修改历史报告或输入 JSON，请保留原有 `log` 记录。

## 5.4 整理中断

整理时先暂存待移动文件，再放入编号目录，避免分组调整造成覆盖。若移动失败，错误信息会给出 `.organize-*` 暂存目录，其中 `plan.json` 记录原路径、暂存文件名和目标路径。请勿删除该目录；恢复文件后再运行整理脚本。检测到未完成暂存时，脚本会停止，不会继续移动文件。
